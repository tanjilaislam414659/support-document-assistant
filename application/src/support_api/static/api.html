Local support API · 0.2.0

Typed request and response schemas: OpenAPI JSON. This local reference requires no external scripts or styles.

GET /health checks the process. GET /ready returns 503 if corpus/index or SQLite is unavailable. GET /metadata lists pinned sources, measured limitations and experimental availability.

Search

POST /search
{"question":"Your documentation question","top_k":3}

Ranked complete source-linked passages. Scores do not establish truth.

Draft and edit

POST /tickets/draft
{"issue":"Your observed issue","environment":{"OS":"User-supplied value"},"selected_sources":[]}

GET /tickets/{id}

PATCH /tickets/{id}
{"expected_revision":1,"human_notes":"Your edited note"}

Select source_id/passage_id pairs returned by search. Unknown IDs are rejected. Every edit creates a revision and invalidates prior review. A stale expected_revision returns 409.

Review

POST /tickets/{id}/review
{"expected_revision":2,"confirm_review":true,"reviewer_label":"local user","note":"Read this saved revision"}

Review records a local user action, not authenticated identity or truth. There is no sending endpoint.

Optional experimental generation

POST /experimental/answer
{"question":"Your question"}

Disabled by default (403). Native explicit --experimental opt-in only. Not packaged or supported in Docker. Output stays unverified, separate from tickets. Application validation is not semantic correctness.
